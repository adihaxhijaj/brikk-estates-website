# Brikk Estates — frontend handoff

> **In this project (after the merge):** the listing JSON files are real data, generated by
> `scripts/import-listings.ts` from the Instagram archive and from listings added in the office admin
> app (`admin/`, see README.md). Do not treat them as seed data or edit them by hand.

This is the frontend of www.brikkestates.com: every page, component, style, translation, font,
and listing photo. It builds and runs on its own. Right now it is a **fully static site with no
backend**. This guide lists every place where a backend should connect.

**Stack:** Astro 7 + TypeScript + plain CSS. No React/Vue, no Tailwind, no CMS.
Node 22.12+.

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # static output in dist/
npm run check    # type check
```

## 2. Integration point: listings data

### Today

`src/content.config.ts` loads `src/content/listings/*.json` with Astro's `glob` loader. Every
page gets listings from **one function**:

```ts
// src/lib/listings.ts
export async function getVisibleListings(): Promise<Listing[]>
```

It removes hidden listings, applies the `CATALOGUE` switches in `site.ts`, and sorts
newest first. All index pages, detail pages, the home page, the sitemap, and the request-form
city list use it.

### Connecting an API or database

Pick one of these:

**Option A: keep the site static and fetch data at build time (simplest).**
Swap the `glob` loader in `src/content.config.ts` for a loader that calls your API. Astro accepts
an async function:

```ts
const listings = defineCollection({
  loader: async () => {
    const res = await fetch(`${import.meta.env.API_URL}/listings`);
    const data = await res.json();
    return data.map((l) => ({ id: l.ref, ...l }));
  },
  schema: /* keep the existing schema, but see the note on images below */,
});
```

Then trigger a rebuild (for example a Vercel deploy hook) whenever an agent adds or edits a
listing. You don't need to touch any page or component.

**Option B: render pages on the server (live data).**
Add an adapter (for example `@astrojs/vercel` or `@astrojs/node`) and set `output: 'server'`.
Then rewrite `getVisibleListings()` to query your API. The `[slug].astro` pages use
`getStaticPaths()`. Replace that with a lookup by `Astro.params.slug`, and return a 404 when
nothing matches.

**Images.** The schema uses `image()`, which expects local files. If photos come from a CDN or
object storage, change `src: image()` to `src: z.string().url()`. Then either add the domain to
`image.domains` in `astro.config.mjs`, or render plain `<img>` tags. Check `Gallery.astro` and
`ListingCard.astro`, which pass `src` to Astro's `<Image>`, and `ListingDetail.astro`
(`ogImage={cover.src.src}`).

### Data contract: one listing

The source of truth is `src/content.config.ts`. `src/content/listings/b301.json` is a full
example. Your API should return this shape, or you can map to it in the loader.

| Field | Type | Notes |
| --- | --- | --- |
| `ref` | `"B301"` | Unique ID, pattern `B` + 3 digits |
| `slugSq`, `slugEn` | string | URL slugs: `/prona/<slugSq>/`, `/en/properties/<slugEn>/` |
| `postedAt` | `YYYY-MM-DD` | Used for sorting |
| `deal` | `sale` \| `rent` | |
| `type` | `apartment` `duplex` `penthouse` `house` `land` `commercial` `office` `warehouse` `building` | |
| `multipleUnits` | bool | Plural labels ("Apartments") |
| `titleSq`, `titleEn` | string | |
| `city`, `cityEn`, `neighbourhood`, `street`, `complex`, `landmark(En)` | string \| null | |
| `country` | `XK` \| `ME` \| `AL` \| null | |
| `isNewBuild`, `developer`, `completion(En)` | | |
| `areaNet`, `areaTerrace` (m²), `plotAres` (land, ares), `areaApprox` | number \| null | |
| `floor`, `floorTo`, `totalFloors`, `bedrooms`, `bathrooms`, `wc` | number \| null | `floor: 0` = ground floor |
| `orientation` | string \| null | Key from `vocab.ts` |
| `features` | string[] | Keys from `vocab.ts` (for example `garage`, `parking`, `furnished`) |
| `legal.*` | bool \| null | ownershipCertificate, notaryContract, contractViaLawyer, inLegalisation, contractWithDeveloper |
| `price`, `pricePerM2`, `pricePerAre`, `rentMonthly`, `deposit`, `minContractMonths` | number \| null | EUR. `priceOnRequest: true` when there's no price |
| `extras.*` | | financing, installments, tradeIn(En), tenanted, rentalIncome, garageOptional |
| `aiVisualisation`, `aiDisclaimerSq/En` | | Shows a notice when renders are AI visualisations |
| `status` | `unconfirmed` `available` `reserved` `sold` `rented` | Controls visibility and badges |
| `hidden` | bool | Never shown |
| `descriptionSq` | string[] (≥1) | One string per paragraph |
| `descriptionEn` | string[] \| null | **Listings with `null` are hidden**. Admin-app listings without English carry the Albanian paragraphs here with `descriptionEnIsTranslation: false`, and the English page says so |
| `images[]` | `{ src, file, width, height, kind, overlay, hasTextOverlay, altSq, altEn }` | At least 1 image. `kind` = room type from `vocab.ts` |
| `coverIndex` | int | Which image is the card cover |
| `instagramUrl` | url \| null | Link to the original post; `null` for listings added in the admin app (the link is then not shown) |

**Rule used throughout the UI:** `null` means "unknown" and the field is left out of the page.
Never send `0` or `""` for a missing value.

### 3c. Listing enquiry

`src/components/ContactPanel.astro` (sidebar on every listing page) currently has only WhatsApp,
phone, Viber, and email links with the listing ref pre-filled. There's no form. If you want
enquiries saved, add a small form here that sends `ref` + name + phone + message.

### To connect a form to your API

In each file's `<script>` block, the button click handler already has `validate()` and
`message()`. Add a `fetch` call next to them (or instead of them):

```ts
const data = Object.fromEntries(new FormData(form));
const res = await fetch('/api/requests', {        // your endpoint
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ ...data, lang: document.documentElement.lang }),
});
```

Then add loading, success, and error states. The error box (`[data-req-errors]` /
`[data-comp-errors]`) and the live hint (`[data-req-hint]` / `[data-comp-hint]`) are already
there to reuse. Add the new strings to **both** `sq.ts` and `en.ts`. `en` is type-checked
against `sq`, so the build fails if one is missing.

⚠️ **Legal text must change too.** The privacy policy and terms currently say the site has no
server that receives data (see the `legal` section in `src/i18n/sq.ts` and `en.ts`). Update
that text once forms save data.

## 4. Search and filters (no backend needed now)

- `SearchPanel.astro` (home page) sends a GET request to `/prona/` with query params.
- `Filters.astro` + `src/scripts/filters.ts` filter the cards that are already on the page, in
  the browser. The page renders every listing for its category, and each card carries
  `data-deal`, `data-category`, `data-city`, `data-hood`, `data-price`, `data-size`,
  `data-beds`, `data-furnished`, `data-new`, and `data-posted`.
- Query params: `deal`, `category`, `city`, `hood`, `pmin`, `pmax`, `smin`, `smax`, `beds`,
  `furnished=1`, `new=1`, `sort` (`newest` | `price-asc` | `price-desc` | `size`).

This works well for about a hundred listings. For thousands, move filtering to an API endpoint
that takes the **same query params**, and render the results on the server.

## 5. Other settings

- `src/config/site.ts` holds the phone, WhatsApp, emails, and Instagram. `CATALOGUE.showUnconfirmed`
  and `showSoldOrRented` decide which statuses appear. Once a backend manages status, you can
  apply those rules in the API instead.
- `astro.config.mjs`: `site` is the production domain, used for canonical URLs, hreflang, the
  sitemap, and JSON-LD. Trailing slashes are on.
- `BRIKK_NOINDEX=1` at build time marks staging builds noindex.
- `vercel.json` sets cache and security headers for Vercel.
- `src/pages/sitemap.xml.ts` and `robots.txt.ts` are generated from listing data, so they pick
  up the new source automatically.
